── finances/models.py ──────────────────────

Category
  fields: id, name(50), type(INCOME|EXPENSE), user(FK→User)
  constraint: unique_together = (name, user, type)
  signal: none
  note: Every category belongs to a specific user (NO global cats)

Transaction
  fields: id, user(FK), category(FK→Category, null=True), amount(decimal),
          date(DateField, default=today), description(text, null), is_deleted(bool),
          created_at(datetime, auto)
  read_only: user
  signal: post_save → check_budget_on_transaction()
    └─ If expense category, checks budget limit:
       ≥80% → creates Notification(threshold=80, BUDGET_ALERT)
       ≥100% → creates Notification(threshold=100, BUDGET_ALERT)
       Dedup: won't send same threshold+category+month notification twice

Budget
  fields: id, user(FK), category(FK→Category), amount_limit(decimal),
          month(DateField - any day of month = full month applies), is_deleted(bool)
  note: Soft delete. month field = entire calendar month applies.

UserProfile (auto-created via post_save signal on User creation)
  fields: user(OneToOne), is_verified(bool), verification_code(6 char),
          reset_code(6 char)
  signal: create_user_profile() auto-creates on User.create
  note: Superusers bypass email verification check on login

UserDevice
  fields: id, user(FK), device_token(255, unique), device_type(50), last_active(auto)

MarketingCampaign
  fields: id, title(200), subtitle(200, null), content(text, markdown),
          image(ImageField, upload_to='campaigns/', optional), cta_text(50), cta_link(255),
          start_date, end_date, is_active(bool), target_filter(ALL|NO_INVESTMENTS|DEBTORS)
  note: Filtered by target_filter logic in ActiveMarketingCampaignView

Notification
  fields: id, user(FK), title(200), message(text), notification_type(BUDGET_ALERT|INFO|SYSTEM),
          is_read(bool), created_at(auto), category(FK→Category, null),
          threshold(int, null - 80 or 100), alert_month(DateField, null), is_deleted(bool)

── obligations/models.py ───────────────────

Loan
  fields: id, user(FK), name(100), loan_type(HOME|CAR|PERSONAL|EDUCATION|OTHER),
          total_principal(decimal), interest_rate(decimal %), start_date, tenure_months(int),
          emi_amount(decimal), is_deleted(bool), created_at(auto)
  signal: post_save → sync_loan_to_transaction()
    └─ On create: auto-creates INCOME transaction category="Loan", amt=total_principal

Debt (Informal lending/borrowing — the "Khata")
  fields: id, user(FK), person_name(100), debt_type(GIVEN|TAKEN),
          amount(decimal), description(text, null), transaction_date(DateField),
          due_date(DateField, null), status(PENDING|PARTIAL|SETTLED), is_deleted(bool)
  signal: post_save → sync_debt_to_transaction()
    └─ TAKEN: auto-creates INCOME transaction category="Borrowing"
    └─ GIVEN: auto-creates EXPENSE transaction category="Lending"

EMIPayment
  fields: id, loan(FK→Loan), due_date, amount_due(decimal), is_paid(bool),
          payment_date(null), remarks(200, null), is_deleted(bool)
  signal: post_save → sync_emi_to_transaction()
    └─ On is_paid=True: auto-creates EXPENSE transaction category="EMI"
       (dedup check on user+description+date to prevent double-log)

  KEY BUSINESS LOGIC / ALGORITHMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Auto Transaction Sync (Backend Signals):
   Loan created     → INCOME tx (category: "Loan", amount: total_principal)
   Debt TAKEN       → INCOME tx (category: "Borrowing", amount: debt.amount)
   Debt GIVEN       → EXPENSE tx (category: "Lending", amount: debt.amount)
   EMI is_paid=True → EXPENSE tx (category: "EMI", amount: amount_due) [dedup check]

2. Budget Alert Engine (Backend Signal on Transaction.post_save):
   On every expense transaction save:
     - Check if Budget exists for same user + category + month
     - Calculate total_spent for that category/month
     - If ≥80%: create Notification(threshold=80) if not already exists
     - If ≥100%: create Notification(threshold=100) if not already exists

3. Marketing Campaign Targeting (ActiveMarketingCampaignView):
   ALL          → show to everyone
   NO_INVESTMENTS → show if user has no Asset records
   DEBTORS      → show if user has Loan OR Debt(TAKEN) records

4. AI Audit Context (AIFinancialAuditView):
   Collects: income_total, expense_total, category_spending{},
             budget_details[], loan_details[], asset_details[], debt_details[]
   Sends to: Gemini 1.5 Flash as a structured prompt
   Returns: markdown financial health report

5. Budget Consumption (Frontend getBudgetConsumptonStats()):
   Aggregates all budgets for current month
   Cross-references allTransactions filtered by category_name + current month
   Returns: {limit: totalBudgetLimit, spent: totalSpent, percent: (spent/limit)*100}

6. Technical Sentiment (FastAPI /stocks/sentiment/{symbol}):
   Fetches 1y daily history via yfinance
   Calculates SMA-50 and SMA-200
   If price > SMA-50 > SMA-200 → BULLISH
   If price < SMA-50 < SMA-200 → BEARISH
   Else → NEUTRAL
   Caches 5 minutes per symbol
